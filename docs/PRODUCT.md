# 모아플랜 제품 명세

## 목적

바보클럽 활동 기획 담당자의 반복 입력과 SNS 홍보 업무를 줄인다. 단체명은 하드코딩하지 않고 단체별 데이터와 키를 분리한다. 일반 회원 가입과 신청은 기존 공식 홈페이지를 사용한다.

## 업무 흐름

후보지 발굴·협의 → 활동 기획 메모와 날짜 저장 → AI 초안 추천 → 선택 항목 반영 및 수정 → 기획 확정 → 홈페이지용 본문 복사 및 신청 링크 등록 → 홍보물 1~8장 구성 → 이미지 최적화·R2 저장 → 홍보 초안 저장 → 승인·예약 게시.

Google Calendar는 활동 상세 버튼을 눌렀을 때만 등록·갱신한다. 웹 내부 달력과 Google 계정의 달력은 구분한다.

## 기본 양식

분류(봉사/친목), 작성 템플릿(봉사/정기모임/번개), 참석가능 등급, 활동명, 시작/종료일과 시간, 신청 마감일시, 장소/주소, 별도 공동 집합 장소와 시간, 모집 정원(0 무제한), 담당자 확인 봉사인증 시간, 알림 문구, 활동안내, 활동일정, 준비물, 이동 안내, 태그, 참고 링크 2개, 첨부 이미지 2개와 상단·하단·본문 배치, 참가 신청 URL, 공통 안내문 포함 여부.

## 기획 원칙

AI는 추천 초안을 반환하고 저장된 사실을 자동 덮어쓰지 않는다. 사용자가 직접 수정한 항목은 초안 반영 기본 선택에서 제외한다. 과거 공지는 문체와 구성 참고이며 날짜·계좌·금액의 근거가 아니다. 협의되지 않은 사실은 확인 필요 표시. 모집 이미지와 후기 이미지를 혼동하지 않는다.

## 운영 상태

활동: draft, confirmed, cancelled, completed.
홍보: draft, scheduled, processing, published, paused, failed, attention.
기획 수정은 홍보물을 stale로 표시하고 scheduled를 paused로 전환한다. Google Calendar도 stale로 표시한다. 처리 중인 활동 수정은 차단한다. 게시 요청 후 결과가 불명확하면 attention으로 전환하고 자동 재시도하지 않는다.

## 데이터 및 운영 제약

첫 버전은 소규모 단체 운영을 위한 PostgreSQL JSONB 상태 저장소를 사용한다. 모든 변경은 행 잠금과 트랜잭션으로 직렬화한다. 로컬 JSON 저장소는 개발 전용, 단일 프로세스 전용이다. 다수 단체의 대규모 운영 전 개별 테이블과 전용 작업 큐로 분리해야 한다.

## 별도 계정으로 검증해야 하는 기능

AI 실제 텍스트·이미지 응답, Meta 게시 권한과 미디어 규격, Google OAuth 및 Calendar 권한, Maps Embed 키와 도메인 제한, 다음 주소 검색 팝업, R2 실물 업로드/서명 URL. 외부 설정이 없는 상태를 성공처럼 표시하지 않는다.
